# Java rule pack

Install the Java rule pack, so `ns rules check` and the build gate enforce its rules. The pack's [README](../../../rules/java/README.md) says what each rule checks. It reads source only, so a Maven repo and a Gradle repo install it the same way, with no change to the build.

1. **Find the pack.** `ns install` symlinks this skill from the nightshift checkout, and the pack sits beside the skills there: `"$(realpath <this skill's directory>)/../../rules/java"`. If that directory is missing, ask the user for the path to their nightshift checkout.
2. **Check the tools.** `java -version` (11 or later; PMD runs on it), `ast-grep --version` and `jq --version`. A missing one: give the user its install command (`apt install openjdk-21-jre-headless`, `uv tool install ast-grep-cli`, `apt install jq`) and wait until all three run.
3. **Run the installer.** `<pack>/install.sh <repo>`. It downloads the PMD release pinned in the checkout's `scripts/ci-tools.d/pmd.toml` (about 130 MB, once; later installs reuse the cached zip), checks its sha256, and copies the pack and PMD to `.nightshift/rules/java/`, with a `.gitignore` that keeps `pmd/` out of git. It seeds the allowlist with the repo's own packages and the packages it imports today, and adds the `rules` row to the Commands table of `docs/agents/stack.md`. A rerun refreshes the pack and PMD and keeps `utils/allowed-package.yml`, `utils/helper-name.yml` and the `ignores` line of `rules/duplicate-helper.yml`. On a failure it writes nothing; show the user its message.
4. **Review the allowlist.** It is the regex in `.nightshift/rules/java/utils/allowed-package.yml`, seeded from what the code imports, so it allows whatever the repo already uses. Show it to the user. Collapse a dependency's packages to its root where they agree (`com.fasterxml.jackson.core|com.fasterxml.jackson.databind` to `com.fasterxml.jackson`), and drop any package the user doesn't mean to keep depending on.
5. **Name the paved helpers.** Add the repo's own helpers that own a job (a static `Strings.isBlank`, the HTTP client wrapper's static factory) to the regex in `utils/helper-name.yml`, and each one's home file to `ignores` in `rules/duplicate-helper.yml`, so a second definition is a finding and the helper itself isn't.
6. **Run it.** `ns rules check --human` from the repo root. Show the user the findings. A `dependency-allowlist` finding on a package the repo means to use is a gap in step 4: fix the allowlist and run it again.
7. **Baseline.** The rest are existing debt. Give the user `ns rules baseline --allow-growth` to accept them. It is theirs to run, since it is what lets existing violations pass.

Done when `.nightshift/rules/java/` holds the pack and PMD, the allowlist names every package the repo imports on purpose, the row is in `stack.md`, and `ns rules check` exits 0 or the user has the baseline command.
