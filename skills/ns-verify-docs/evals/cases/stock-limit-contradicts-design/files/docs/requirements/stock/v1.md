## Summary

The warehouse manager and purchasing learn which items are running low before a picker finds an empty bin. Auto-reordering is left out.

## User stories

S1. As a warehouse manager, I want to see which items are running low, so that no bin runs empty unnoticed.

S2. As a purchaser, I want one list of low items each morning, so that I can place every order in one go.

## Must have

| ID | Requirement | Why / source | Verified by |
|---|---|---|---|
| STOCK-1 | The `status` command marks each item whose available stock (on hand minus unexpired reservations) is below that item's threshold | S1. Last month on-hand stock looked fine but was all reserved | CLI test with a fully reserved item |
| STOCK-2 | A `low-stock` command prints every item below its threshold, one per line, with SKU, available quantity and threshold | S2. Purchasing runs it each morning | CLI test |
| STOCK-3 | `reserve` and `fulfil` take no more than 10% longer, median of 1000 calls, than before this change | Notes: they run all day. 10% decided by Priya, 2026-09-28 | Benchmark before and after |

## Should have
