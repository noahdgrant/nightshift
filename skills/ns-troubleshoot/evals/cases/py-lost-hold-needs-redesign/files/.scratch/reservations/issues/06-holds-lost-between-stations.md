# Holds sometimes vanish when two stations reserve together

Status: needs-repro
Category: bug
Priority: priority:high

Reported by: Alex (packing stations 1 and 2)

## Description

Both packing stations run the CLI against the same `inv.json` on the shared drive. Every so often, when both stations reserve at nearly the same moment, both get the same reservation ID back, and later only one of the two holds is in the state file. The other order is picked, then `fulfil` ships the wrong quantity or says the reservation doesn't exist. It happens a few times a week, never when one person works alone.

## What we run

```
# station 1
python3 -m inventory --state /mnt/share/inv.json reserve BOLT-M6 2
# station 2, a moment later
python3 -m inventory --state /mnt/share/inv.json reserve BOLT-M6 3
```

## Expected

Two reservations, with different IDs, both held.

## Actual

Sometimes:

```
R0012: 2 x BOLT-M6 until 2026-03-02T09:30:00
R0012: 3 x BOLT-M6 until 2026-03-02T09:30:00
```

and `status` shows only 3 reserved.
