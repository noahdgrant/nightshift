# Holds sometimes expire before their time

Status: needs-repro
Category: bug
Priority: priority:medium

Reported by: Sam (packing station)

## Description

Now and then a hold runs out early. We reserve with a 5 minute hold, pick the order, and fulfil it about four and a half minutes later. Most days that works. Maybe one time in three, `fulfil` says the reservation has expired, even though the `reserve` output said it was good for five minutes. Running the same steps again usually works, so we can't make it happen on demand.

## What we run

```
python3 -m inventory --state inv.json reserve BOLT-M6 4 --ttl 5
# ... pick the order, about 4.5 minutes ...
python3 -m inventory --state inv.json fulfil R0007
```

## Expected

The reservation can be fulfilled until the time `reserve` printed.

## Actual

Sometimes:

```
inventory: error: reservation 'R0007' has expired
```
