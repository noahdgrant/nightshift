# D55: The Python rule pack lives in rules/python/

## Decision

Builds on D50. The Python rule pack lives in `rules/python/` and composes `ast-grep` (`suppression-reason`, `dependency-allowlist`, `duplicate-helper`) and a small script (`file-size.sh`), with a strict `ruff.toml` (`F401`, `F821`, `F841`, `B006`, `RUF100`: unused import, undefined name, unused variable, mutable default argument, unused suppression) passed with `--config` so no repo ruff config leaks in. Both print `file:line:col: message`, which `ns rules check` reads, so the pack needs no wrapper. `ns-setup` installs it into `.nightshift/rules/python/`; the dependency allowlist, the duplicate-helper names and the duplicate-helper `ignores` line (each helper's home module) are the pack's only per-repo data, in `utils/allowed-package.yml`, `utils/helper-name.yml` and `rules/duplicate-helper.yml`, so a rerun copies the pack and keeps those three. The `rules` row is one file, `stack-row.md`, that `ns-setup` inserts and `run.sh` runs. `rules/python/tests/run.sh` runs both tools on each rule's `pass*.py` and `fail*.py` examples, in CI and `scripts/ci-local.sh`.

## Reason

Agreed in #234. The pack sits in `.nightshift/` because that path needs a human merge, so an agent can't loosen a rule or allow a dependency to get its unit through. Ruff holds only rules that add to `suppression-reason` and the repo's own lint, and none of its ruleset floods `evals/fixtures/py-inventory`. `ruff --config` replaces the repo's own ruff config for the run, so a repo's ignores can't hide a pack rule. `ast-grep scan` skips dot directories by default, so the row passes `--no-ignore hidden --globs '!.git'` to scan them, as ruff does, and keep `.git` out. ast-grep holds the allowlist because no other tool here can: `import-linter` contracts only forbid imports and ruff has no allowlist, so `import-linter` waits for a module-boundary rule. The standard library is a hand-kept util (`utils/stdlib-module.yml`, the public names in Python 3.12's `sys.stdlib_module_names`) plus any `_`-prefixed name, so the allowlist names only what the repo adds. `file-size` is a script because an ast-grep node starts at its first token, so a rule on the module can't count blank lines at the top of a file. `import-linter` is not used: its contracts only forbid imports and have no allowlist. Duplicate helpers are matched by name only, a list of stdlib-covered names that the repo extends; a duplicate by shape needs two definitions compared and stays in review. The short report has no rule field, so a finding's `rule` is empty and its message carries `error[<id>]`; the baseline matches on the snippet anyway. `run.sh` also runs the allowlist's accept branch on a temp copy of the pack with a non-empty allowlist, and `ns rules check` with the row on a failing file. Ruff's `PGH003`/`PGH004` are not selected: they reject a blanket `# noqa` even with a reason, stricter than the rule and a duplicate of `suppression-reason`. `ns-setup` got no eval case: its pack step is a deterministic copy plus one `stack.md` row, which `rules/python/tests/run.sh` covers, also under a decoy `GIT_DIR`, and real eval runs are scheduled separately. Spec: `rules/python/README.md`.
