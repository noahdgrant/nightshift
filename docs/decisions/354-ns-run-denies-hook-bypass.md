# ADR-354: ns run denies hook bypasses in claude phases

## Decision

`ns run` enforces `ns-contract`'s Git hooks rule for claude phases (#354, settled in #350). Each claude phase gets `--settings` with one `PreToolUse` hook on `Bash`, `Edit`, `Write`, `MultiEdit` and `NotebookEdit` that runs the hidden `ns guard-hooks`. It tokenises the Bash command, so a quoted mention or a heredoc body is not a command, and denies `--no-verify`/`-n` on `git commit`, `--no-verify` on push, merge and rebase, a `core.hooksPath` override or write, a write, move or delete under `.githooks/`, `chmod` or `find -delete` aimed at those paths, and `HUSKY=0`, `SKIP=`, `GIT_DIR`, `--git-dir` and the `GIT_CONFIG_*` variables, naming the rule. The user's own settings are untouched. The guard reads through reserved words, wrappers (`env`, `sudo`, `nice`, `xargs` and the rest, with their value options), `eval`, `sh -c`, command substitutions, heredoc bodies and a `cd` into `.githooks/`, nested at most 8 deep. A word built by an expansion (`$VAR`, brace expansion) where a flag goes, or an opaque command word next to `git`, a guarded subcommand or a protected path, is denied, because it could be `--no-verify`; the phase writes it out literally. `HUSKY=0` and `SKIP=` are denied in any command, git or not, since an `export` outlasts the call. The hook command is `ns guard-hooks || exit 2` and `ns run`, dry runs included, refuses to start when no `ns` can be found, because Claude Code lets a call through when a hook exits with anything but 2. A harness command that already passes `--settings` is a deliberate usage error: claude takes one `--settings`, and merging would mean parsing a value that is a file path or JSON and keeping the user's hooks ahead of or behind ours. It breaks a user whose `[harness.claude]` command carries `--settings`; they move those settings to `~/.claude/settings.json` or the project's `.claude/settings.json`, which claude merges with ours. Only the `ns run` phases get the hook. The `ns eval` trial runner is exempt because it runs on scratch fixtures, not the repo's hooks, and `ns ask --write` is exempt because the user or a skill starts it by hand in a directory of their choosing, outside a unit's phases and outside the gate's reach, so there is no phase contract to enforce; a user who wants the guard there adds `--settings` to their `command_write` themselves. The guard also reads `git -c alias.X=...` together with the arguments given to the alias, `git rebase -x` and `git submodule foreach` command strings, `git config` writes of an alias with a skip flag or a `!` value and of `include.path`, `git config --edit` and a section removal or rename that names `core`, a shell with no `-c` fed a heredoc or herestring (it runs the text, so the phase writes `sh -c` instead), `.git/hooks` and `.git/config` as well as `.githooks/`, and `env -S` behind other env options. The `ns` path in the hook and the gate comes from one helper, `exe::ns_exe` (`current_exe` with the kernel's ` (deleted)` suffix removed; when that file is gone, as for an `ns watch` unit whose pinned binary was replaced and removed, the `ns` on `PATH`; an error only when neither exists). `ns watch` execs `/proc/self/exe` to keep the night's own binary, but a command line handed to claude or the gate runs in other processes where `/proc/self` names them, so the hook cannot use it. Other harnesses have no such hook; the gate run after every phase that moves HEAD (#351) is their backstop.

## Reason

The guard is a best-effort denylist: it stops accidental or lazy bypass, and the gate is the control. It does not chase arbitrary command runners (`flock`, `taskset`, `ssh`, `parallel`, `watch`), a command held wholly in a variable (`X='git commit -n'; $X`), a shell fed by a pipe, script, `trap` or `source`, `python -c` or `node -e`, archive or download tools that write hooks, globs or variables in `rm` paths, git plumbing such as `commit-tree`, or further environment variables. A shell parser that covers every form (an alias in the user's git config, a script the phase writes and runs, a binary the phase replaces mid-run) is out of reach. The hook stops the plain forms, and the gate catches what slips past. Failing closed on expansions costs a legitimate `git commit $FLAGS` or an unquoted `git push $REMOTE`; a variable after a literal argument (`git push origin $BRANCH`) passes, and so does a whole-word `"$BRANCH"` on merge and the like. On push a whole quoted variable passes only after a literal argument or `--`, or when the word ends in literal text (`"$V/remote.git"`); the phase writes other names out. The hook also reads the payload's `cwd` and a `${...}` body whole, and the `--settings` JSON carries `"disableAllHooks": false` while `.claude/settings*.json` is protected like the hooks, which is best effort: a user-level or managed setting can still override the flag.
