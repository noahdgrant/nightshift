# `ns doctor`

## `ns doctor`

Prints the config path, whether it exists and parses, and each configured role with its resolved harness, model, read-only and write commands, and whether the binary is on PATH. `distinct_harnesses` lists the providers in use, so a skill can tell whether two roles get a cross-provider check. `harnesses` reports which of `claude`, `codex`, `cursor-agent`, `gemini` and `opencode` are on PATH, and `pinning`, how `ns run` pins the skills that harness's phases see: `snapshot` for claude, `partial` for codex (it reads the snapshot through `.agents/skills`, next to the user's installed skills, unless the repo tracks `.agents/skills`: then the live directory stays and `ns run` logs `skills_unpinned`), `none` for cursor-agent (unconfirmed), gemini and opencode (`docs/factory/run.md`, "Pinned skills and phase settings"). `forge` reports, per forge, whether it is `configured`, whether a token resolved (`token_resolved`), the `account` the forge's API returns for that token (`gh api user`, `glab api user`), and the `table` it came from. For the forge `origin` is on it also reports the `repo` from `origin`'s URL, whether the token can read it (`repo_readable`; false is a problem), and for an SSH origin the account `ssh -T` greets (`ssh: {dest, account}`). Fields that don't apply are null. The token itself is never printed. `warnings` lists what doesn't stop a night: an SSH account that differs from the token's, an SSH host that greets no account, a set `GH_TOKEN` or `GITLAB_TOKEN` that overrides the config, an SSH `origin` with no keepalive, a main checkout that is not on the default branch, and a linked worktree that holds the default branch, so the main checkout cannot switch to it. `ssh_keepalive` reports whether pushes to an SSH `origin` send keepalives (`ok`), and what sets `ServerAliveInterval` (`source`: `GIT_SSH_COMMAND`, `core.sshCommand`, or `ssh config`, from `ssh -G`); without one, a push whose pre-push hook runs for minutes can lose its idle connection. `claude_phases` reports that `ns run` phases and `ns eval` trials run claude with auto-memory off (`auto_memory: false`) and the variable that does it (`env`). `skill_dirs` reports, per harness (`claude`, `codex`, `agents`, `cursor`), the `path` that `ns install --harness` links into and `ns_skills`, how many `ns-*` skills it holds (0 when the directory is missing). `problems` lists anything that would make `ns ask` fail, and a forge token that doesn't resolve.

Exits 1 when any check fails (`ok` is false, and `problems` says which), 0 otherwise; the report is printed either way. Warnings never change the exit code.
