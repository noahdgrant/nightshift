# `ns watch`

## `ns watch [--once] [--until HH:MM] [--max-units N] [--parallel N] [--dry-run] [--factory <dir>]`

Lists open issues labelled `[queue] ready_label` with `gh`, drops issues whose first line, after any leading `🤖` disclosure line, is `Blocked by: #a, #b` with any blocker open, and issues an open PR closes (unless the PR is from the issue's own unit branch, which resumes at the merge step), then sorts by the first matching `[queue] order` label and the issue number. For each unit it swaps the ready label for the in-progress label, fetches `origin`, and starts `ns run --issue <n> --base origin/<default>` as a child process on a snapshot of the config and factory definition taken at start, up to `--parallel` (or `[limits] parallel`, default 1) at once, each with `--cpus max(1, cores / parallel)`, each free slot taking the first ready issue whose brief's predicted `touches` overlap no running unit's, else the first (`[queue] overlap_ignore` names files that never count; `docs/factory/watch.md`, "Parallel units"); a usage limit in one unit pauses the others at their next phase, and the budget counts every unit's spend (`docs/factory/watch.md`, "Parallel units"). Afterwards: `merged` removes the in-progress label (and `human_merge_label` from the PR), `done` sets `done_label` and labels the unit's PR, if it has one, `human_merge_label` (default `needs-human-merge`, created in red when missing) with a comment saying why it needs a human merge, so `gh pr list --label needs-human-merge` is the merge queue (every comment and issue `ns watch` posts opens with `🤖 *Posted by nightshift, an AI agent.*`), `split` (triage split the issue into child issues) sets `split_label` (default `status:split`, created when missing), and at start and between units each issue under it closes once its children are all completed, or goes to `stuck_label` when one was closed as not planned (`split_parents` in the output; `docs/factory/watch.md`, "Split parents"), `stuck` (or a `done` that needs a human merge, whose PR is labelled too) sets `stuck_label` and comments the reason, `budget` (also a runner lock or merge lock wait cut short by `--until`, or a budget found spent once the locks are held) returns the issue to the ready label and stops, and `paused` sleeps until the usage limit resets and resumes the same unit, or returns the issue and stops if the reset is past `--until`. While main's CI is red it starts only the fix issue, and stops with `stopped: "main_red_unfixed"` when that issue's unit ends `stuck`, `budget` or `split` with main still red (`docs/factory/watch.md`, "Main's CI"). At start it returns open in-progress issues that no live `ns run` holds to the ready label, keeping their worktrees so the units resume (`requeued` in the output). At start and between units it removes the worktrees of units a human merged since, as `ns clean` does (`cleaned` in the output, `clean` under `--dry-run`). On SIGINT or SIGTERM it starts nothing new, passes the signal to each unit's `ns run`, which ends its running phase's process group (SIGTERM, then SIGKILL after 5 s), returns every unit's issue to the ready label, prints the summary with `stopped: "SIGINT"` or `"SIGTERM"`, and exits 130 or 143. A second `ns watch` on the repo exits 5. `--dry-run` prints the ordered queue, with the running units each ready issue overlaps (`overlaps`), the skip reasons, the in-progress issues it would return (`requeue`), the label it would put on a PR that needs a human merge (`human_merge_label`), and each split parent with what it would do (`split_parents`). `gh` and every phase get `GH_TOKEN` from `[forge.github]` in the config, or from the environment when it is already set (see [`[forge]`](../../cli/README.md#forge)). `--until` is local time, and the `until` and `reset_at` it prints are local with their offset (`2026-10-09T06:30:00-04:00`). `NS_NOW` (unix seconds) pins the clock for tests.
